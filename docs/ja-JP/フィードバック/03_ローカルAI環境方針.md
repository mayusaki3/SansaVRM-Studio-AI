# SansaVRM Studio AI ローカルAI環境方針

## 1. 目的

SansaVRM Studio AI におけるローカル AI 実行環境の候補と、当面の方向性を整理する。

## 2. 前提

- NVIDIA GPU を主対象とする。
- Windows + WSL2 または Linux を優先対象とする。
- AI 環境は Studio 本体に必須ではない。
- AI 機能は Adapter 経由で利用する。
- OSS ベースを優先する。

## 3. 論点

- 画像から 3D を生成する標準候補。
- ComfyUI を中継基盤として採用するか。
- VRAM 要件をどこまで対象にするか。
- CPU 実行をどこまで許容するか。
- Windows ネイティブと WSL2 の優先順位。

## 4. 案

### 4.1 Hunyuan3D 系

画像から 3D メッシュ + テクスチャ生成候補。

用途:

- Character
- Asset
- Prototype
- VRM 前処理

### 4.2 TRELLIS 系

高品質 PBR 系 3D アセット生成候補。

用途:

- PBR
- Environment
- XR Asset
- O3DE / Unity 用 Asset

### 4.3 TripoSR 系

軽量・高速な単画像 3D 化候補。

用途:

- Prototype
- Concept
- Quick Reconstruction

### 4.4 ComfyUI 統合

ComfyUI を AI 実行ハブとして扱う案。

期待する役割:

- workflow 管理
- provider 差異吸収
- image pipeline 統合
- local node 管理

## 5. 未決事項

- 標準推奨 GPU スペック。
- VRAM 最低ライン。
- Docker 化するか。
- Portable 構成を作るか。
- ComfyUI 非依存運用をどこまで考慮するか。

## 6. 次アクション（任意）

- 推奨ローカル AI 環境を整理する。
- Adapter 接続方式を整理する。
- ComfyUI workflow との関係を整理する。
