# SansaVRM Studio AI 実行形態方針

## 1. 目的

SansaVRM Studio AI の実行形態、配布形態、UI 方式について、正式仕様化前の方針を整理する。

## 2. 前提

- 想定する使い方は、開発用と利用者用の 2 種類とする。
- 開発用は Git リポジトリを clone して使用する。
- 利用者用はインストーラー必須ではなく、zip 解凍で使用できる形を許容する。
- UI はブラウザベースとする。
- UI がブラウザベースである以上、ローカル UI であっても Web サーバーを使用する構成を許容する。
- ローカル単体利用では、localhost または WebView 経由で UI を利用できることを想定する。
- LAN 内の他 PC から UI を利用する場合は、ネットワーク公開可能な Web サーバーとして起動する必要がある。
- Windows と Linux の両方で動作させることを想定する。
- AI 環境は任意機能であり、Core 実行に必須としない。

## 3. 論点

- ブラウザ UI をどの実行方式で提供するか。
- Web サーバーを内蔵するか、ローカルファイルとして提供するか。
- localhost 専用モードと LAN 公開モードをどう分けるか。
- LAN 公開時の認証、アクセス制御、ファイルアクセス権限をどう扱うか。
- Windows / Linux で同じ配布構成にするか。
- 開発者向け構成と利用者向け構成をどこまで分けるか。
- zip 解凍後に追加セットアップを必要とするか。

## 4. 案

### 4.1 案A: ローカルアプリ + ブラウザ UI

SansaVRM Studio AI をローカルアプリとして起動し、UI 表示にブラウザ技術を使用する。

想定構成:

- Core 実行プロセス
- ローカル UI
- ローカルファイル入出力
- localhost 通信
- 必要に応じた WebView または既定ブラウザ起動

この案では、利用者から見るとローカルアプリとして扱える。

### 4.2 案B: 静的 HTML + ローカルファイル操作補助

UI を静的 HTML / JavaScript として提供する。

ただし、ブラウザのセキュリティ制約により、ローカルファイル操作、外部プロセス実行、大容量 3D データ処理に制約が出る可能性がある。

### 4.3 案C: 通常の Web サーバー方式

Web サーバーとして起動し、ブラウザからアクセスする。

この案は実装上は扱いやすい。

ローカル単体利用では localhost のみで待ち受ける。LAN 内の他 PC から利用したい場合は、明示的にバインドアドレス、ポート、アクセス制御を設定してネットワーク公開する。

### 4.4 案D: Web サーバー必須 + 動作モード分離

UI は常に内蔵 Web サーバー経由で提供する。

動作モードを以下のように分ける。

- local mode: `127.0.0.1` または `localhost` のみで待ち受ける。
- lan mode: 指定した LAN インターフェースで待ち受ける。
- restricted mode: 認証またはアクセス制御を有効にして待ち受ける。

この案では、実装方式を単純化しつつ、ローカル UI と LAN 共有 UI を同じ仕組みで扱える。

### 4.5 採用候補

当面は案Dを採用候補とする。

SansaVRM Studio AI は、UI を内蔵 Web サーバー経由で提供する。通常は localhost のみで起動し、利用者が明示的に指定した場合に限り LAN 公開を許可する。

## 5. 未決事項

- UI 実装方式。
- デスクトップアプリ化の有無。
- WebView を使用するか、既定ブラウザを使用するか。
- zip 配布時のディレクトリ構成。
- Windows / Linux での起動スクリプト名。
- AI Adapter 利用時の外部プロセス起動方式。
- LAN 公開時の認証方式。
- LAN 公開時のファイルアクセス制御。
- 初期設定で LAN 公開を禁止するか。
