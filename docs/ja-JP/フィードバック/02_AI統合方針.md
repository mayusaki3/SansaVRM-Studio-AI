# SansaVRM Studio AI AI統合方針

## 1. 目的

SansaVRM Studio AI における AI 統合の基本方針を整理する。

本メモでは、AI 機能を Core 機能から分離し、AI 環境がない利用者でも利用可能な構成を維持するための方向性を整理する。

## 2. 前提

- AI 機能は任意機能とする。
- AI 環境を内蔵前提にしない。
- ローカル AI 実行環境を優先する。
- API サービス依存を前提にしない。
- Adapter により provider 差異を吸収する。
- 生成 AI の出力は不完全である前提で Validator と連携する。

## 3. 論点

- AI 実行を Studio 内に内蔵するか、外部ツール連携にするか。
- ComfyUI、Hunyuan3D、TRELLIS、TripoSR などをどのように抽象化するか。
- AI 実行結果の provenance をどのように保持するか。
- モデル管理、ライセンス、GPU 必須条件をどこまで扱うか。
- API ベースの AI サービスを公式対象に含めるか。

## 4. 案

### 4.1 Adapter 分離方式

AI 機能は Adapter として分離する。

例:

- Hunyuan3D Adapter
- TRELLIS Adapter
- TripoSR Adapter
- Meshy Adapter
- ComfyUI Adapter

Studio 本体は Adapter API のみを扱う。

### 4.2 Core 非依存方式

Viewer、Validator、Converter、Report Viewer は AI 機能に依存しない。

AI 環境が存在しない場合でも、Studio の主要機能は動作可能とする。

### 4.3 provenance 保持方式

AI 生成時の以下情報を保持できる構造を検討する。

- generator
- model
- prompt
- negative_prompt
- seed
- input_images
- generation_time
- pipeline
- source_type

## 5. 未決事項

- Adapter API の正式定義。
- 非同期ジョブ管理方式。
- GPU 不在環境での UI 表示。
- AI 実行ログ保持範囲。
- モデルダウンロード支援の有無。

## 6. 次アクション（任意）

- AI Adapter の責務範囲を整理する。
- provenance 保持形式を検討する。
- ローカル AI 環境の構築フローを整理する。
