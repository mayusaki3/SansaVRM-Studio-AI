# アーキテクチャ仕様

## 1. 目的

本仕様は、SansaVRM Studio AI の初期アーキテクチャを定義する。

SansaVRM 側からの回答に基づき、Studio AI 側では SansaVRM の Core Semantic / Preservation Compatibility / Validation / Runtime Integration / Import Export の責務分離を前提にする。

## 2. 前提

- Studio AI は SansaVRM の authoring frontend として機能する。
- Studio AI は SansaVRM Core semantic を直接拡張しない。
- policy / restriction / provenance / integrity proof / diagnostics / export transformation は Core semantic として扱わない。
- Studio AI は、制作状態から検証状態、流通状態、エクスポート状態へ進む workflow を扱う。
- Studio AI で生成・編集した情報は、SansaVRM 側の Layer 責務に従って分類する。

## 3. Layer 対応

## 3.1 Core Semantic 対応

Studio AI は、以下を Core semantic 候補として扱う。

- layered asset structure
- authoring / distribution / export state separation の semantic boundary
- reversible / irreversible export の意味論

Studio AI は、Core semantic に属する可能性がある情報を生成した場合、review / rewrite / validation を通す。

## 3.2 Preservation Compatibility 対応

Studio AI は、以下を Preservation Compatibility concern として扱う。

- policy
- restriction
- provenance
- generation history
- source_raw
- preserve_only
- adapter raw
- unsupported information
- integrity proof
- transformation history

## 3.3 Validation 対応

Studio AI は、以下を Validation concern として扱う。

- topology_quality
- rigging validation result
- humanoid compatibility validation
- integrity validation result
- tamper validation result
- signature verification result
- validator diagnostics
- trust diagnostics
- conversion diagnostics
- copyright risk assessment result

## 3.4 Runtime Integration 対応

Studio AI は、以下を Runtime Integration concern として扱う。

- runtime compatibility
- rigging runtime compatibility
- humanoid runtime compatibility
- platform runtime requirement
- viewer/runtime execution condition
- runtime-specific adapter contract

## 3.5 Import Export 対応

Studio AI は、以下を Import Export concern として扱う。

- export_profiles
- reversible / irreversible export execution
- policy rewrite
- metadata filtering
- mesh filtering
- hidden mesh bake
- material merge
- platform export target

## 4. Studio AI 内部モジュール

## 4.1 Core UI

Core UI は、ブラウザベース UI を提供する。

責務:

- project 操作
- asset 表示
- layer 表示
- validation result 表示
- export profile 選択
- local / LAN mode UI

## 4.2 Project Manager

Project Manager は、Studio AI 内部の作業単位を管理する。

責務:

- source input 管理
- generated image 管理
- decomposition result 管理
- prompt pack 管理
- validation result 管理
- export artifact 管理

## 4.3 AI Preprocess Module

AI Preprocess Module は、ローカル AI を用いた前処理を扱う。

責務:

- image / prompt 入力
- asset type 推定
- layer decomposition
- multi-view generation
- prompt pack generation
- downstream image / video generation support

## 4.4 Risk Assessment Module

Risk Assessment Module は、SansaVRM 接続前の画像・中間成果物について、著作権侵害可能性評価を扱う。

責務:

- prompt risk evaluation
- source image risk evaluation
- reference candidate evaluation
- insufficient evidence reporting
- recommendation generation

## 4.5 SansaVRM Bridge

SansaVRM Bridge は、Studio AI 内部成果物を SansaVRM 側の Layer 責務へ対応付ける。

責務:

- Core semantic 候補抽出
- Preservation metadata 出力
- Validation result 出力
- Import Export request 生成
- Runtime compatibility 情報生成

## 5. 動作形態

Studio AI は内蔵 Web サーバーを使用する。

動作モード:

- local mode: localhost のみで待ち受ける。
- lan mode: 明示的に指定された LAN インターフェースで待ち受ける。
- restricted mode: 認証またはアクセス制御を有効にして待ち受ける。

初期設定は local mode とする。

## 6. 禁止事項

Studio AI は以下を行ってはならない。

- policy 情報を Core semantic identity として扱う。
- AI pipeline detail を Core semantic identity として扱う。
- representation hash を semantic equivalence の唯一条件とする。
- export profile の結果を review / rewrite / validation なしに Core semantic へ戻す。
- 外部 AI サービスへ制限付き素材を無断送信する。

## 7. 次アクション

- decomposition schema を定義する。
- authoring workflow を定義する。
- local AI runtime を定義する。
- 最小 PoC の実装構成を定義する。
