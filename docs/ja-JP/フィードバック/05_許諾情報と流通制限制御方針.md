# SansaVRM Studio AI 許諾情報と流通制限制御方針

## 1. 目的

SansaVRM Studio AI における生成物の表現制限、許諾情報、禁止事項設定、流通制御の基本方針を整理する。

本メモでは、制作ツール上で生成物そのものを制限するのではなく、生成・編集・検出結果を SansaVRM の許諾情報および禁止事項設定に反映し、利用・配布・流通段階で制限を掛ける仕組みを検討する。

## 2. 前提

- SansaVRM Studio AI は制作・変換・確認ツールであり、原則として生成物の表現内容を制作段階で禁止しない。
- 成人向け表現、暴力表現、グロテスク表現などを含む生成物も、ツール上の作成対象としては一律に排除しない。
- ただし、生成物の内容、状態、利用条件、禁止事項は、SansaVRM の許諾情報および禁止事項設定に自動反映する。
- 現状の SansaVRM の許諾情報設計では、流通制限に必要な情報の一部は既に対応可能である。
- 流通・公開・利用可否は、許諾情報、禁止事項、検出結果、配布先のルールに基づいて制限する。
- 人型キャラクターの制作では、着せ替えを想定すると素体は衣服なしである必要がある場合がある。
- 衣服なし素体は、使用・流通・公開・共有に制限が必要な状態として扱う。
- SansaVRM はファイルフォーマットであるため、ファイル単体の改ざんを完全に防ぐことはできない。
- そのため、改ざん防止ではなく、利用時・流通時・検証時に改ざんまたは許諾情報の欠落を検出できる仕組みを重視する。
- 検出可能性を高める仕組みは SansaVRM 本体側にも必要であり、SansaVRM 側へ仕様フィードバックする。

## 3. 論点

- 制作時に表現を禁止しない場合、どのように流通制限へ接続するか。
- 現状の SansaVRM 許諾情報で対応できる範囲と、追加が必要な範囲をどう分けるか。
- 許諾情報と禁止事項設定を、手動入力だけでなく自動判定・自動反映できるか。
- 人型キャラクターの衣服状態、年齢属性、成人向け要素、暴力表現、グロテスク表現などをどの粒度で分類するか。
- 裸体素体、下着状態、衣装付き状態、公開可能状態をどう区別するか。
- ユーザーが許諾情報や禁止事項を削除・改ざんした場合に、どの時点で検出するか。
- SansaVRM 本体が保持すべき検出用情報と、Studio 側で扱う UI / workflow の責務境界をどう分けるか。

## 4. 案

### 4.1 案A: 制作自由 + 許諾情報自動反映

SansaVRM Studio AI では生成物の作成自体を制限しない。

ただし、生成物の内容や状態に応じて、以下のような情報を SansaVRM に自動反映する。

- adult_content
- violent_content
- grotesque_content
- nude_body_base
- underwear_state
- clothed_state
- distribution_restricted
- public_share_restricted
- requires_clothing_layer
- requires_viewer_warning
- derivative_use_restricted

この案では、制作自由度を保ちながら、流通・利用段階で制限を掛けられる。

### 4.2 案B: 生成時ブロック方式

特定表現を生成時点で禁止する。

この案は単純だが、SansaVRM Studio AI の用途である制作・変換・検証の自由度を狭める可能性がある。

また、着せ替え前提の人型キャラクター素体など、制作上必要な状態まで禁止される可能性がある。

### 4.3 案C: 状態管理 + 流通ゲート方式

生成物に対して状態フラグを付与し、流通・公開・共有・エクスポート時にゲート判定を行う。

例:

- 制作可能: true
- ローカル保存可能: true
- VRM / SansaVRM 変換可能: true
- 公開可能: false
- 外部共有可能: false
- 成人向け流通のみ可能: true
- 衣装レイヤー必須: true

この案では、制作段階と流通段階を分離できる。

### 4.4 案D: 利用時検出方式

SansaVRM ファイルは、複製・編集・変換が可能なファイルフォーマットであるため、改ざんを完全に防ぐことはできない。

そのため、以下のような検出可能性を重視する。

- 許諾情報の存在確認
- 禁止事項設定の存在確認
- policy / license / restriction 領域のハッシュ確認
- 生成・編集履歴との整合確認
- 変換レポートとの整合確認
- 署名がある場合の署名検証
- 署名がない場合の警告表示
- 流通時または利用時の validator による再検証

この案では、改ざん防止を絶対保証せず、利用された時点でどこかの検証段階により検出されることを目標とする。

### 4.5 採用候補

当面は案A、案C、案Dの組み合わせを採用候補とする。

SansaVRM Studio AI は生成物の制作自体を制限しない。ただし、生成・編集・検出結果を許諾情報および禁止事項設定へ反映し、エクスポート、公開、共有、配布、外部サービス連携時に制限を掛ける。

改ざん対策は、ファイル単体で完全に防止するのではなく、利用時・流通時・検証時に検出できることを重視する。

## 5. 未決事項

- 現状の SansaVRM 許諾情報で対応できる範囲。
- SansaVRM 側に追加が必要な許諾情報スキーマ。
- SansaVRM 側に追加が必要な禁止事項スキーマ。
- 成人向け、暴力、グロテスク、裸体、下着、衣装付き状態の分類粒度。
- 人型キャラクター素体の扱い。
- 衣装レイヤー必須判定の定義。
- 流通制限を掛けるタイミング。
- 署名を使う場合の対象範囲。
- 改ざん検出にハッシュ、履歴、検証レポートを使う場合の対象範囲。
- 外部プラットフォーム向け出力時の制限反映方式。

## 6. 次アクション（任意）

- 許諾情報・禁止事項・流通制限の最小スキーマ案を作る。
- 人型キャラクター素体と衣装状態の判定ルールを整理する。
- 改ざん検出方式の候補を整理する。
