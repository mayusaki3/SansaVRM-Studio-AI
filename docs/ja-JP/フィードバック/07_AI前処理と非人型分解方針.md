# SansaVRM Studio AI AI前処理と非人型分解方針

## 1. 目的

SansaVRM Studio AI の最初の AI サポート機能として、プロンプトまたは画像から 3D モデル生成前処理用の多視点画像、分解画像、調整用プロンプトを生成する方針を整理する。

本メモでは、人型キャラクターだけでなく、非人型キャラクター、動物、メカ、ロボット、乗り物、道具、外装付き構造物なども対象に含める。

また、本段階の出力は 3D 生成前処理に限定せず、画像生成、動画生成、設定画生成、参照素材生成などへ接続できる中間成果物として扱う。

## 2. 前提

- 最初の AI サポートは、3D モデルそのものの生成ではなく、3D 生成前処理を目的とする。
- 入力は、テキストプロンプト、単一画像、複数キャラを含む画像、複数設定画を含む画像を想定する。
- 出力は、多視点画像、分解画像、構造化メタデータ、追加調整用プロンプトを想定する。
- 人型キャラクター専用の分解単位に固定しない。
- 対象物の種類に応じて、分解単位を切り替える。
- 本段階では、裸体素体、成人向け表現、衣装分離、内部構造推定など、外部 AI サービスでは扱いにくい中間生成物を扱う可能性がある。
- そのため、本段階の AI 処理はローカル AI 実行を原則とする。
- ローカル AI 実行により、制作中データ、制限付き表現、未公開設定画、内部構造情報を外部サービスへ送信しない構成を目指す。
- 本段階の出力は、3D 生成だけでなく、2D 画像生成、動画生成、ポーズ展開、表情差分生成、設定資料生成にも再利用できる。

## 3. 論点

- 人型以外の対象をどの分類で扱うか。
- 動物の毛皮、羽毛、鱗、甲殻などを衣装や外装と同じ扱いにするか。
- メカの外装と内部機構をどう分離するか。
- ロボットの装甲、フレーム、関節、配線、アクチュエータをどう分類するか。
- 多視点生成時に、内部構造を推定するか、外観のみ生成するか。
- 3D 生成前処理として必要な情報と、SansaVRM 本体へ渡す情報をどう分けるか。
- ローカル AI を必須とする範囲と、任意で外部サービスを利用できる範囲をどう分けるか。
- 3D 生成用出力と、画像生成・動画生成用出力を同じ中間成果物から派生させるか。

## 4. 案

### 4.1 案A: 対象タイプ別分解テンプレート

入力対象を分類し、対象タイプごとに分解テンプレートを切り替える。

候補:

- humanoid_character
- non_humanoid_character
- animal
- creature
- mech
- robot
- vehicle
- prop
- environment_asset

### 4.2 案B: 汎用レイヤー方式

対象タイプに依存しすぎず、以下のような汎用レイヤーへ分解する。

- base_structure
- outer_surface
- covering
- appendage
- accessory
- internal_mechanism
- movable_part
- hidden_part
- material_region
- effect_region

この案では、人型の body / clothing / hair も、より汎用的な layer にマッピングできる。

### 4.3 案C: 表面材質を独立分類する

動物やクリーチャーでは、衣装ではなく表面材質が重要になる。

候補:

- skin
- fur
- feather
- scale
- shell
- armor
- metal_panel
- fabric
- leather
- glass
- emission_part

毛皮や羽毛は、衣装ではなく outer_surface または covering として扱う。

### 4.4 案D: メカ内部構造分解

メカ、ロボット、外装付き構造物では、外観と内部構造を分離する。

候補:

- outer_armor
- inner_frame
- joint
- actuator
- cable
- sensor
- weapon_mount
- power_unit
- decorative_panel

ただし、画像から内部構造を推定する場合は推測生成になるため、明示的に `inferred` として扱う。

### 4.5 案E: ローカルAI限定前処理

本段階では、裸体素体、成人向け状態、未公開キャラクター設定、内部構造、流通前の制限付き素材を扱う可能性がある。

そのため、3D 生成前処理、分解画像生成、多視点生成、調整用プロンプト生成は、原則としてローカル AI で実行する。

外部 AI サービスを利用する場合は、ユーザーが明示的に選択した場合のみとし、送信対象データとリスクを表示する。

### 4.6 案F: downstream media generation 連携

本段階の出力を、以下へ接続できる中間成果物として扱う。

- 3D model generation
- character sheet generation
- image generation
- video generation
- pose variation generation
- expression variation generation
- clothing variation generation
- material reference generation

これにより、同じ分解結果・多視点結果・プロンプト情報から、3D 生成だけでなく 2D / video 系ワークフローにも接続できる。

### 4.7 採用候補

当面は案A、案B、案C、案D、案E、案Fを組み合わせる。

最初の PoC では、人型キャラクターに限定せず、対象タイプを検出し、タイプ別テンプレートと汎用レイヤーの両方へマッピングする。

また、分解・多視点生成・制限付き中間素材生成はローカル AI 実行を原則とし、出力は 3D 生成、画像生成、動画生成へ接続できる中間成果物として扱う。

## 5. 想定出力

### 5.1 多視点画像

- front
- back
- left
- right
- top
- bottom
- detail

対象によって必要な視点を切り替える。

例:

- 人型: front / back / left / right
- 動物: front / back / left / right / top
- メカ: front / back / left / right / top / internal cutaway candidate
- 道具: front / back / side / top / bottom

### 5.2 分解画像

- 全体画像
- 外観レイヤー画像
- 表面材質別画像
- 可動部画像
- 内部構造候補画像
- アクセサリ画像
- 装備品画像

### 5.3 構造化メタデータ

例:

```json
{
  "asset_type": "mech",
  "layers": [
    {
      "layer_id": "outer_armor",
      "source": "visible",
      "confidence": 0.92
    },
    {
      "layer_id": "inner_frame",
      "source": "inferred",
      "confidence": 0.41
    }
  ]
}
```

### 5.4 downstream 用成果物

- prompt pack
- negative prompt pack
- view prompt set
- layer prompt set
- character sheet prompt
- image generation prompt
- video generation prompt
- pose variation prompt
- material reference prompt
- provenance metadata

## 6. SansaVRM側へのフィードバック候補

- SansaVRM の layer 概念は、人型の body / clothing / hair に限定しない方がよい。
- layer は、外観、内部構造、表面材質、可動部、隠し部位を表現できる必要がある。
- layer には `visible`、`hidden`、`inferred`、`generated`、`author_verified` などの由来情報が必要になる可能性がある。
- 動物の毛皮や羽毛などは、clothing ではなく outer_surface / covering / material_region として扱う必要がある。
- メカの外装と内部機構は、別 layer として扱う必要がある。
- 3D 生成前処理由来の情報は provenance として保持できる必要がある。
- 3D 以外の画像生成・動画生成へ派生した成果物についても、provenance と policy を保持できる必要がある。

## 7. 未決事項

- 最初の PoC で対象タイプをどこまで扱うか。
- 動物、メカ、ロボットの優先順位。
- 推定された内部構造を出力してよい条件。
- ユーザー追加指示による再分解・再生成の UI。
- SansaVRM layer との対応関係。
- ローカル AI 実行環境の最小構成。
- 外部 AI サービスを任意利用可能にする場合の警告・同意 UI。
- 画像生成・動画生成へ接続する出力形式。
