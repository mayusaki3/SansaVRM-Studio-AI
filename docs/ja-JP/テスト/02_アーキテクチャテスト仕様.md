# アーキテクチャテスト仕様

## 1. 目的

SansaVRM Studio AI のアーキテクチャ仕様に基づき、Layer 責務分離と Studio AI 内部モジュールの責務が期待通り定義されていることを確認する。

## 2. テスト方針

- Core semantic と Preservation / Validation / Runtime / Import Export の責務分離を確認する。
- policy / provenance / diagnostics / export transformation が Core semantic として扱われないことを確認する。
- local / lan / restricted mode の存在を確認する。

## 3. テストケース

### TC-ARCH-001

目的:

policy 情報が Core semantic identity として扱われないことを確認する。

入力:

```json
{
  "field": "adult_content",
  "expected_layer": "Preservation Compatibility"
}
```

期待結果:

- Core Semantic に分類されない。
- Preservation Compatibility concern として扱われる。

---

### TC-ARCH-002

目的:

layered asset structure が Core semantic 候補として扱われることを確認する。

入力:

```json
{
  "field": "layered_asset_structure"
}
```

期待結果:

- Core Semantic candidate として扱われる。

---

### TC-ARCH-003

目的:

integrity proof と integrity validation result が別 Layer に分類されることを確認する。

入力:

```json
{
  "integrity_proof": true,
  "integrity_validation_result": true
}
```

期待結果:

- integrity proof は Preservation Compatibility concern。
- integrity validation result は Validation concern。

---

### TC-ARCH-004

目的:

export profile detail が Import Export concern として扱われることを確認する。

入力:

```json
{
  "field": "export_profile_detail"
}
```

期待結果:

- Import Export concern として扱われる。
- Core semantic として扱われない。

---

### TC-ARCH-005

目的:

初期動作モードが local mode であることを確認する。

入力:

```json
{
  "startup_config": {}
}
```

期待結果:

- mode = local
- bind address = localhost または 127.0.0.1

---

## 4. カバレッジ観点

- Layer 責務分離
- Core semantic 汚染防止
- Preservation metadata
- Validation result
- Import Export concern
- Runtime mode
