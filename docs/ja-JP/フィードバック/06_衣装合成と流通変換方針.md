# SansaVRM Studio AI 衣装合成と流通変換方針

## 1. 目的

SansaVRM Studio AI におけるキャラクター素体、衣装、アクセサリーなどの合成状態と、制作状態から流通状態への変換方針を整理する。

本メモでは、制作時に保持する内部状態と、公開・配布・流通用に変換した状態を分離し、SansaVRM の許諾情報および禁止事項設定と連携する構成を検討する。

## 2. 前提

- SansaVRM はキャラクター素体、衣装、アクセサリーなどを個別に保持できることを想定する。
- Studio AI 上では、内部的に裸体素体や成人向け状態を保持する場合がある。
- 着せ替え、衣装変更、物理調整、ウェイト調整では裸体素体が必要な場合がある。
- 流通用・公開用・共有用には、内部状態をそのまま公開しない場合がある。
- 流通状態では、許諾情報および禁止事項設定に従い、不要部分の削除、マスク、統合、焼き込み、メッシュ除去を行う場合がある。
- 制作状態と流通状態は同一ではない。

## 3. 論点

- 制作時内部状態と流通状態をどう分離するか。
- キャラクター本体と衣装を個別許諾として扱うか。
- 合成後の見た目と内部保持状態が異なる場合をどう扱うか。
- 流通時に削除した部分をどう記録するか。
- 全年齢版生成時に、どの処理を自動変換として許可するか。
- 変換後の許諾情報をどう更新するか。
- 元データ保持版と流通版をどう識別するか。

## 4. ケース

### 4.1 ケース1

状態:

- 見た目は衣装付き
- キャラクター内部状態は成人向け
- 衣装は全年齢
- 合成後見た目は全年齢相当

想定:

- 制作状態では成人向け属性を保持
- 流通時は viewer warning または restricted distribution を適用
- 内部裸体素体保持状態を metadata に記録

### 4.2 ケース2

状態:

- 見た目は衣装付き
- キャラクター内部状態は成人向けだった
- 流通用に局部などを削除済み
- 衣装は全年齢
- 合成後見た目は全年齢

想定:

- 流通用エクスポート時に不要部位を除去
- または hidden mesh bake を実施
- または texture bake / merge を実施
- 流通版では全年齢許諾へ変更
- 元データ保持版との関係を provenance に保持

## 5. 案

### 5.1 案A: layered asset 方式

以下を個別に保持する。

- body layer
- clothing layer
- accessory layer
- hidden layer
- restricted layer

流通時に layer ごとに export policy を適用する。

### 5.2 案B: export profile 方式

用途別に export profile を切り替える。

例:

- authoring profile
- local editing profile
- private sharing profile
- adult distribution profile
- all ages distribution profile
- VRChat upload profile

profile ごとに以下を切り替える。

- mesh removal
- hidden mesh bake
- texture bake
- material merge
- metadata filtering
- policy rewrite
- license rewrite
- viewer warning

### 5.3 案C: reversible / irreversible export 区別

変換を以下に分ける。

- reversible export
- irreversible export

irreversible export では以下を許可する。

- mesh delete
- texture rewrite
- merge bake
- vertex collapse
- hidden surface remove

これにより:

- 制作状態
- 流通状態
- 軽量化状態
- 全年齢版

を分離できる。

### 5.4 採用候補

当面は案A、案B、案C の組み合わせを採用候補とする。

SansaVRM Studio AI は、制作状態と流通状態を分離して扱う。Studio AI は、制作状態から全年齢版・公開版・軽量版などへの変換を支援する。
