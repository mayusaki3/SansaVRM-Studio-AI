# AIモデル選定と権利確認チェックリスト方針

## 1. 目的・位置付け

SansaVRM Studio AI のAIモデル選定、制作時の権利認識、許諾状態管理、公開前チェックリストについて、2026-11-17までの検討結果を記録する。

本書は**確定した方針と未確定の設計課題を区別する検討記録**であり、既存の正式仕様を直ちに上書きしない。正式仕様・テスト仕様への反映は整合性確認後に行う。

## 2. AIモデル構成の検討前提（選定未確定）

- ローカル実行できる公開ウェイトのAIモデルを原則とする。
- 非公開制作時には成人向け・暴力・グロテスク表現を含む広範な創作を想定する。法令・第三者の権利・既存の利用条件を無効化する意味ではない。
- 生成用AIと公開審査・助言用AIを分離する。
- 生成画像等の類似性認識と、使用素材・学習データ・モデル等の権利／利用許諾の確認を分離する。
- 画風・キャラクター等の個性を反映するLoRA／追加学習、将来的なモデル改造・AI支援によるモデル開発を検討する。
- 国・地域、公開先、商用利用等の条件を参照して助言する。AI単独で法的適合を保証しない。
- モデル候補の個別採用、標準対応範囲、ライセンス検証、VRAM要件は未確定。

## 3. 確定事項：制作と公開の分離

1. 権利・許諾に関する懸念を検出しても、Studio AIは**原則として制作・生成・編集を拒否せず**、検出結果を記録する（A案）。
2. ただし、制作行為自体に適用される法令や、既存の明示的な利用条件・制限との整合は別途検討する。
3. 公開時は、対象アセットに適用される未解決チェック項目が残る限り、Studio AI の公開手続きを許可しない。
4. Studio AIの評価は助言であり、最終的な判断と公開責任はクリエーターが負う。チェックリスト完了は法的適法性の保証ではない。

## 4. 確定事項：検出・記録の二系統

### 4.1 生成結果の類似性

- 生成・編集結果と既存作品、キャラクター、意匠、商標等との類似性や関連の可能性を検出・記録する。
- 類似性の検出のみを権利侵害の確定とみなさない。
- 誤検出、許諾不要、修正、許諾取得等の判断経緯を記録する。

### 4.2 使用素材の権利・許諾

- 参照画像、入力アセット、学習データ、LoRA、基盤モデル、派生モデル、部品等の取得元・利用条件・許諾範囲・未許諾状態を追跡する。
- 権利が存在することと、実際の利用が許諾範囲外であることを区別する。
- 素材やモデルの依存関係と制作履歴を保持し、公開対象への影響を確認する。

## 5. 確定事項：チェックリストと解決権限

1. 検出した問題候補は制作工程でチェックリスト化し、対象、検出根拠、状態、対応履歴を保持する。
2. チェック項目の解決はクリエーターが実施する。**判断理由・根拠の記録を必須**とする（B案）。
3. AIの警告とクリエーターの判断が対立しても、クリエーターは根拠を記録して解決できる。AIの再承認は必須としない（A案）。
4. AIの元の警告、検出根拠、解決判断は履歴として保持する。
5. 外部のローカルAI、クラウドAI、専門家、権利者、審査機関等へ任意で評価を依頼できる拡張経路を想定する。
6. **外部評価は参考情報・証拠として追加するのみ**で、自動解決は行わない（A案）。正式な権利者許諾は評価意見とは区別し、許諾範囲を記録する。
7. 非公開素材を外部サービスへ送信する際は、明示的な許可を必要とする。

## 6. 確定事項：管理単位・依存関係・差し替え

1. チェックリストは**アセット単位**で管理し、素材・学習モデル・生成物・部品等の依存関係を追跡する（A案）。
2. 公開判定では、公開対象に関係するチェック項目を依存関係から集約する。依存関係だけで権利侵害と断定しない。
3. 素材の差し替え・削除時にも、元の使用履歴とチェック項目を保持する（A案）。
4. 差し替えによる影響を再評価し、必要な項目をクリエーターが根拠付きで解決する。素材を削除しただけで学習済みモデルや生成物への影響が消えるとはみなさない。

## 7. 確定事項：変更時と公開直前の再確認

### 7.1 制作途中（都度A案）

- アセット変更時は、**変更の影響を受ける解決済みチェック項目のみ**再確認待ちにする。
- 変更前の解決結果・根拠・判断履歴は保持する。
- 影響判定の詳細アルゴリズムは未確定。

### 7.2 最終公開前（B案）

- 公開直前には、公開対象に関係する**すべてのチェック項目**を、解決済みを含めて再確認する。
- この最終確認が完了しない限り、Studio AIの公開手続きを許可しない。
- 最終確認の証跡・対象アセット版・公開先条件を記録する。具体的な再確認操作や再評価の自動化範囲は未確定。

## 8. 確定事項：コンテンツ利用条件と機能利用条件の分離

### 8.1 コンテンツ利用条件

- 著作権・利用許諾・表現内容・倫理基準・公開先条件等を管理する。倫理基準は必ずしも権利者による許諾ではないため、公開条件として区別する。
- AIによる未確定のリスク検出は、原則として制作を止めずチェックリストへ登録する。
- 公開前の最終確認とクリエーターの根拠付き判断を必要とする。

### 8.2 機能利用条件

- アセットや部品に対する表示、編集、抽出、分解、変換、転用等の操作許可・禁止を管理する。
- **明示的に禁止された操作はStudio AIのUIおよび実行経路で拒否する（A案確定）。** UIだけでなくAPI・ワークフロー実行経路にも適用する。
- 例：3Dモデルの表示は許可されていても、テクスチャの抽出・他アセットへの再利用は禁止できる。抽出と再利用は異なる操作として扱う。
- 利用者による警告解決をもって機能利用禁止を解除しない。禁止条件の変更・権限更新方式は別途設計する。

### 8.3 機能利用許諾が未設定の場合（確定）

機能利用許諾は、少なくとも次の3状態を区別する。

| 状態 | 動作 |
|---|---|
| 明示的に許可 | 当該操作を許可する |
| 明示的に禁止 | 当該操作を拒否する |
| 未設定 | クリエーターに判断を求め、判断理由・根拠を記録したうえで当該操作の可否を決定する |

- 未設定を暗黙の許可とは扱わない。
- クリエーター判断は明示的な禁止を上書きできない。
- 判断記録には、対象アセット、操作内容、判断者、日時、判断結果、判断理由・根拠を含める。
- 判断は権利者からの許諾取得を意味しない。必要に応じてコンテンツ利用側の確認項目にも関連付ける。
- **判断結果はアセット・操作単位で保持し、同一条件では再利用する（A案確定）。** 同じアセット・操作・許諾条件なら操作のたびの再判断は不要とする。
- アセットまたは許諾条件が変更された場合は、以前の判断の有効性を再確認する。変更前の判断・根拠は履歴として保持する。
- 明示的な禁止条件が追加された場合、以前のクリエーター判断による許可より禁止条件を優先する。
- アセットの変更を識別する粒度、条件の同一性判定方法、再確認対象の具体的な抽出規則は未確定。

### 8.4 派生アセットにおける判断の再確認（A案確定）

- 派生元の機能利用許諾、クリエーターの判断結果、判断理由・根拠、履歴を、派生関係をたどれる形で保持する。
- **機能利用許諾が未設定の場合に派生元で行った許可判断は、派生先に自動適用しない。**
- 派生先で同じ操作を行う場合も、その派生先アセットについてクリエーターの判断と理由・根拠の記録を必要とする。
- 派生を複数回繰り返しても、各段階の判断と元の判断履歴を追跡できるようにする。目的は、繰り返し派生した結果、以前の判断を失念して誤って操作する事故を防ぐことにある。
- 明示的な禁止条件は派生先でも遵守する。派生に伴う許諾条件の継承・変更ルールの詳細は別途設計する。
- 同一派生先アセットで一度判断した結果の再利用は、第8.3節のアセット・操作単位の方針に従う。

### 8.5 派生元の許諾変更と未確認事項（B案確定）

- 派生アセットは派生時点の許諾条件を保持する。派生元の許諾条件が後から変更されても、派生先に保存された操作許可・禁止を自動変更しない。
- 派生元の許諾変更を検出した場合、影響を受ける派生先に**「許諾変更・未確認」**のチェック項目を登録し、変更前後の条件・関連アセット・判断履歴を追跡可能にする。
- 未確認項目はクリエーターが変更内容を確認し、判断理由・根拠を記録するまで保持する。公開前には、第7.2節の最終公開前チェックと同様に再確認を必須とする。
- 変更前の条件・判断履歴は消去しない。
- 本方針は**派生元の条件変更を派生先へ自動反映しない**ことを定めるものであり、派生先自身の許諾条件が直接変更された場合の操作制御とは区別する。
- 後から変更された条件が既存派生物へ法的に及ぶかは契約・許諾内容による。未確認事項の解決は法的な適法性を保証しない。
- **許諾変更が未確認の間も、派生先では派生時点の機能利用条件に従って制作を継続できる（A案確定）。** 未確認であることのみを理由に制作操作を停止しない。
- ただし、影響する未確認チェック項目が残る間は、その派生先を含む対象のStudio AIによる公開手続きを保留する。第7.2節の公開前確認にも含める。
- 派生先自身に直接適用される明示的な禁止操作は従来どおり拒否する。派生元の変更が派生先へ法的に適用されるかは別途確認する。
- **許諾変更の確認結果に応じて、クリエーターが理由・根拠を記録して未確認事項を解決できる（A案確定）。** 変更後の条件への一律な自動適合は要求しない。
- 「既存派生先への影響なし」と判断した場合は、その根拠とともに解決済みとする。
- 「影響あり」と判断した場合は、必要な対応が完了するまで公開を保留する。対応完了時の判断・根拠・対応履歴を保持する。
- 判断できない場合は未確認状態を維持し、公開を保留する。
- 解決済みでも第7.2節の最終公開前確認の対象とする。クリエーター判断は法的な適法性を保証しない。
- **派生元の許諾条件が再度変更された場合、変更ごとに新しい未確認事項を登録する（A案確定）。** 以前の変更に対する「影響なし」等の判断を、新しい変更へ自動適用しない。
- 各変更と未確認事項、判断理由・根拠・対応履歴を個別に対応付け、過去の判断は履歴として保持する。
- 新しい変更も、未確認中の制作継続・公開保留・最終公開前の再確認について本節および第7.2節の方針を適用する。
- **同一の許諾変更通知は変更IDで重複判定する（A案確定）。** 同じ変更IDの通知を再受信しても確認項目は重複作成しない。
- 変更IDは発行元と組み合わせて識別し、発行元間のID衝突を防ぐ。
- 異なる変更IDは内容が類似していても別の変更として扱い、それぞれ確認項目を作成する。
- 重複受信しても既存の確認状態・判断結果・理由・根拠・履歴を初期化しない。
- 変更IDの発行方式、同一IDで内容が異なる通知への対応、通知の到達保証は未確定。
- 条件変更の影響範囲の判定方法は未確定。

### 8.6 保護の目的と限界

- 画面キャプチャ等の迂回を完全に防止することはできない。
- 目的は技術的な完全防止を保証することではなく、**Studio AI自身が権利者の明示した操作制限を遵守すること**にある。
- 著作権ライセンス等の条件は操作と公開の双方に関係する場合があるため、コンテンツ利用条件と機能利用条件は内部責務として分離しつつ、必要に応じて両方を評価する。
- 禁止操作の試行・判定理由の監査記録を設ける方針とし、保存範囲・期間・記録方式は未確定。

## 9. 既存仕様との整合確認事項（未解決）

- [01_著作権侵害可能性評価仕様](../仕様/01_著作権侵害可能性評価仕様.md) は画像・中間成果物のリスク評価を定義する。今回の素材権利管理と公開チェックリストは追加の検討対象。
- [16_governance_evaluation仕様](../仕様/16_governance_evaluation仕様.md) は既存のSansaVRM governanceをauthorityとし、禁止された編集・分解・学習等の操作を実行しない方針を規定している。本書で、明示的な機能利用禁止とAIによる未確定リスクを区別した。具体的な操作ごとの適用条件は正式仕様への反映時に整合確認する。
- [08_rights_provenance方針](./08_rights_provenance方針.md) の取得・派生・組立履歴と、チェックリストの関連付け方式を検討する。
- 公開ガードと既存のexport / redistribute / publish操作の境界、外部送信時の同意、国・地域別ルールの版管理、チェック項目の状態遷移、証拠保存形式は未確定。
- Workflow IDE Frameworkとの共通化候補であるEnvironment / Dependency ManagementはRequirement宣言とProvider実装を分離し、具体的なAI Runtime等の知識をStudio AI側に残す。Framework側の正式仕様は未確定。

## 10. 次アクション

1. 確定した二分類を既存governance仕様の操作別条件に対応付ける。
2. チェック項目・依存関係・証拠・最終公開確認のデータモデルを設計する。
3. 正式仕様とテスト仕様を整備した後に実装する。
4. ローカルAIモデルの候補を、生成・類似性検出・素材権利確認・公開助言の役割ごとに比較検証する。
